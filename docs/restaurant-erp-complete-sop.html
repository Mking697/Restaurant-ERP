How to read this SOP

Live/current is not the same as released everywhere. “Available” means source-backed database functionality exists. “Built; browser/UAT pending” means code, API and automated checks exist, but a real user click-through is still outstanding. “Verified local” means isolated local QA passed; it does not prove production deployment.

Planned is never shown as live. Blue planned blocks describe the approved final design from gaps.md. Deferred and superseded items remain visible. There is no fabricated completion percentage; only exact gap counts and named states are shown.

The operating journey

Final planned ERP: P4 to P7

These are approved destinations, not live screens. P1–P3 residuals also remain visible below so “core done” is not confused with “everything done.”

P4 · Complete restaurant order, kitchen, invoice and payment lifecycle
Distinct Fast Food and Conventional workflow configuration; persisted open orders, table assignment and KOT revisions; proforma versus immutable final invoice; payment receipts allocated to invoice with approved split-tender and part-payment; manager-authorized void/reversal; image-based touch POS; atomic takeaway tokens; platform references; real provider intake only after a provider is named; unpaid/pending settlement separated from fulfillment.
P5 · Full shift drawer and Head Office cash custody
First opening float, live sales/tender/pending-order summary, shift-linked cash expenses and drawer movements, then a final route to Head Office with in-transit custody, receiver acknowledgment, discrepancy and retained-float rules. Current next-shift handover remains available but is not the same as HO receipt.
P6 · Consent-based customer membership and loyalty
Voluntary WhatsApp community invitation; membership registry with explicit consent; append-only reward earn/redeem/expire/reverse ledger; opaque revocable member QR; safe repeat ordering using current availability, prices and taxes. A captured phone number is not consent or membership.
P7 · Client UAT, release evidence and documentation
Trace every one of the 42 gap IDs to implementation, accepted scope change or honest deferral. Run the connected chain from PO and partial receipt through production, transfer, sale, void, count, expense and HO cash. Verify real disposable SQL/HTTP, concurrency, authorization, desktop/mobile browser UAT, migration/readback and authorized production smoke before calling the final ERP released.
P1–P3 honest residuals and deferrals
Prepared/Semi-FG batch expiry; prepared physical count history; actual-cutting browser proof; fixed-recipe actual lot cost and downstream cost carry; cost deviation band; some transfer cost valuation; partial vendor-payment allocation; broader non-quality return reasons; tax handling for debit notes; prepared replenishment suggestions. RAW reorder conversion and the HO review queue are verified locally only, with release/persistent migration pending. Provider intake is blocked/no current scope until a real provider is named.
